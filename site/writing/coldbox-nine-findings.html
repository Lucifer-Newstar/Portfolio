Nine findings in a ColdBox banking app, and how I fixed them

A full penetration-test engagement against my own application: SecureBank, a small ColdBox banking app built twice, once vulnerable and once hardened, with every fix proven by executed tooling.

Source on GitHub

SecureBank is a deliberately small simulated banking application on the ColdBox/CFML stack (ColdBox 8.3, Lucee 6.2, MariaDB 11.8), implemented twice: a vulnerable build and a hardened build with the same features. Everything runs on loopback only, all accounts and balances are synthetic fixtures, and the test harness refuses non-loopback targets. The point was never the app. The point was running the complete application-security lifecycle on it: develop, test, scan, identify, remediate, verify, automate.

The findings cover four classes. SQL injection in the login and search flows, where the queries were concatenated strings, fixed with cfqueryparam and proper validation. Reflected and stored cross-site scripting from raw output, fixed with context-aware encoding and a Content Security Policy. Session fixation, where the session identifier never rotated at login, fixed by rotating it and invalidating the old token. And a transfer endpoint that did not verify account ownership, fixed so both accounts must belong to the caller, with the transfer bounded and atomic.

A fix you cannot demonstrate is just a claim, so the repo is built around proof. A differential harness sends the same 18 requests to both builds: 18 out of 18, the vulnerable build fails and the secured build holds. The TestBox suites pass 31/31 on one side and 44/44 on the other, and seven environment gates (G1 to G7: boot, database, BCrypt, sessions, TestBox, datasource) run before any of the security tooling starts.

The scanner story is honest about its limits. OWASP ZAP runs baseline and active scans, Gitleaks hunts secrets, Trivy covers dependencies and containers. Semgrep has no CFML parser, so instead of pretending it scanned anything, I wrote cfscan, a small in-repository CFML scanner, with its heuristic rules labelled as heuristics. A severity-based quality gate reads the reports, and the one accepted exception lives in a written ledger as EX-001 rather than being quietly ignored.

What I took from the engagement is that security work is evidence work. The findings index has a chapter per finding, including what the evidence does not prove, and the limitations doc lists the gaps, like untested concurrency. Reports distinguish executed checks from checks with no results. Fourteen screenshots capture the running applications. It is all in the repo, MIT licensed, for local and isolated educational use.
